Validation report

OpenPrism 1.0.0 · generated 2026-11-03 · 808 of 808 checks passed

OpenPrism's statistical results were evaluated in four independent ways:

  1. Accuracy against certified values. The NIST Statistical Reference Datasets (StRD) give certified results computed with 500-digit arithmetic for deliberately difficult problems: univariate statistics, one-way ANOVA, linear regression (including the ill-conditioned 10th-degree Filip polynomial and the Longley data) and 26 nonlinear regression problems, each from two starting points. Accuracy is reported as the log relative error (LRE), the number of correct significant digits (McCullough 1998, 1999).
  2. Agreement with R. About 290 results from base R 4.x and established CRAN packages (survival, MASS, metafor, psych, car, lmtest, quantreg, circular, nlme, coin) on classic datasets. Where R itself is known to be inexact (root-finding tolerances, 1 − pchisq() cancellation, coarse numerical Hessians), the result is additionally checked against its defining equation evaluated in exact or 50-digit arithmetic.
  3. Statistical calibration. Monte-Carlo simulation through the application's own code: tests must reject at the nominal rate when the null hypothesis is true, and 95% confidence intervals must cover the true value 95% of the time.
  4. Reproducibility. Every analysis gives bit-identical output when repeated and in a fresh process (resampling methods use fixed seeds), and invariances that must hold mathematically (shift, scale, ordering, relabelling) hold to ≥ 9 digits.

All checks run through openprism.stats.run, the same code path the application uses, with full-precision output. Rerun everything with python validation/run_validation.py; the automated test-suite runs the same checks.

Problems found and fixed

While building this suite the following problems were found and fixed:

  • Derived data tables (outputs of transforms, normalization, residuals…) were stored with only 6 significant digits; they now keep 15.
  • Data with a large constant part (e.g. 1 000 000 000 000.4) lost up to 10 digits in ANOVA, t tests and SDs, because such numbers cannot be held exactly in binary. Values are now centred on a common offset in exact decimal arithmetic before conversion (NIST SmLs07–09: from 3 to 15 correct digits).
  • Polynomial and ill-conditioned multiple regression lost all digits on NIST Filip. These fits are now solved from the exact decimal data in 80-digit arithmetic (Filip: from 0 to ≥ 10.5 digits for every coefficient).
  • The nonlinear fitter failed to converge on two NIST problems from the first starting values and stopped early on others. It now combines Levenberg-Marquardt and a trust-region method and keeps the best solution: all 52 NIST nonlinear fits converge to the certified solution (≥ 5 digits for every parameter, median 8.5).
  • Mann-Whitney and Wilcoxon P values were labelled "exact" when ties forced an approximation; both now compute the exact conditional distribution with ties (as StatXact / R coin) and label the method truthfully.
  • The Peto-Peto weighted log-rank test used Peto's survival estimate at the previous event time instead of the current one (Klein & Moeschberger §7.3); it now agrees with an independent implementation to 15 digits.
  • The aligned-rank-transform ANOVA could break ties between values that are equal in exact arithmetic but differ by one unit in the last place after alignment; aligned values are now rounded to 12 significant digits before ranking (ARTool agreement: from 2.5 to 14.7 digits).
  • Numbers were parsed leniently ("1,5" was read as 15). Only the strict mathematical format is now accepted (decimal point, no thousands separators); anything else is flagged and reported, never reinterpreted.
