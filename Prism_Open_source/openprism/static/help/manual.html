OpenPrism user manual

OpenPrism is an open source workbench for organizing experimental data, choosing and running the right statistical analysis, fitting curves, and making publication-quality graphs and figures. This manual explains every feature and gives practical guidance on interpreting results.

Statistics are a tool, not an oracle. OpenPrism computes results carefully (validated against SciPy and statsmodels), but the validity of any analysis depends on your experimental design and on the assumptions of the test. When in doubt, talk to a statistician before you collect the data.

Getting started

OpenPrism follows a simple workflow that mirrors how experiments are analyzed:

  1. Create a data table (Ctrl+T or New table). Pick the table type that matches the structure of your experiment — see Choosing a table type.
  2. Enter your data. Type values, paste a block from Excel (Ctrl+V), or import a CSV/Excel file.
  3. Analyze (Ctrl+K). Choose a test, select the data sets and options, and click Analyze. A result sheet appears under Results.
  4. Graph. Every new table gets a graph automatically. Choose a graph type, error bars and formatting in the right-hand inspector. Analyses on the same table can be shown on the graph (fitted curves, significance brackets).
  5. Make a figure. Combine several graphs and text on a layout page, add panel labels and export a 300-dpi PNG, an SVG or a PDF.
  6. Save the project (Ctrl+S) or download it as a portable .oprism file.
Everything is live. When you change a value in a data table, every analysis and graph that uses that table is recalculated the next time you open it. You never need to “re-run” after editing data.

Look for the small ? buttons throughout the program: they open a short explanation for that exact spot, with a link to the relevant section of this manual. F1 opens the manual at the topic for whatever you are looking at.

Projects, saving & files

A project contains all data tables, analyses, graphs, layouts and notes of one experiment or paper.

  • Save (Ctrl+S): stores the project on the OpenPrism server, in its projects/ folder. The first time you are asked for a name. Save as stores a copy under another name.
  • Open (Ctrl+O): lists projects saved on the server, newest first.
  • Download project file: saves a .oprism file (plain JSON) to your computer, ideal for archiving, e-mailing to colleagues or attaching to a lab notebook. Open it with File → Open project file.
  • Autosave: the current project is continuously saved in your browser. If you close the tab by accident, it is restored the next time you open OpenPrism. This is a convenience, not a backup — save your work.
  • Project notes (Info section): free text for methods, sample IDs, notebook references, etc.

An orange dot next to the project name means there are unsaved changes. Click the project name to rename the project.

Undo / redo

Ctrl+Z undoes the last change (data edits, analyses, graph formatting, layout moves); Ctrl+Y or Ctrl+Shift+Z redoes. Up to 80 steps are kept. While typing in a text box, these keys act on that text box instead.

Choosing a table type

Unlike a general spreadsheet, OpenPrism tables are structured: the table type tells the program how your experiment was designed, so it can offer the analyses and graphs that make sense.

The table type cannot be changed after creation, but you can copy and paste the values into a new table of a different type.

XY tables

Every row has one X value (yellow column) and one or more Y values. Each data set (A, B, C …) is a separate curve, e.g. control and treated.

  • Use replicate subcolumns when you have several Y values for the same X (technical or biological replicates). Graphs then show mean ± error bars and nonlinear regression can fit every replicate or only the means.
  • For dose-response curves, enter the logarithm of the concentration as X (e.g. −9 for 1 nM) and use the log(agonist) equations; or enter concentrations and use the [Agonist] vs response equation with a logarithmic X axis.
  • Rows do not need to be sorted, and X values may repeat.

Column tables

Each column (data set) is a group; each row is one subject or replicate. Groups may have different sizes — leave cells blank.

For paired or repeated-measures designs (same subject measured under each condition, matched pairs, or data from the same experimental run), keep the matched values on the same row. Rows with missing values are skipped by paired analyses.

Enter raw values, not means. Column graphs (scatter dot plots, bars, box plots) are computed from the raw data.

Grouped tables

Grouped tables arrange data by two factors: the row titles define one factor (e.g. Week 1, Week 2 …) and the data sets define the other (e.g. Wild type, Knockout). Use replicate subcolumns for the individual values in each cell — two-way ANOVA needs at least two replicates per cell to test for interaction.

Grouped tables are graphed as grouped or stacked bars, grouped scatter plots, lines across rows, box plots or heat maps.

Contingency tables

Rows are groups (e.g. exposed / not exposed, treatment / placebo) and columns are outcomes (disease / no disease). Each cell contains the number of subjects — never a percentage, mean or rate. For a 2×2 table, put the treatment (or exposure) of interest in the first row and the outcome of interest in the first column; odds ratio and relative risk are then reported in the natural direction.

Survival tables

Each row is one subject.

  • X: the time from the start of the study to the event, or to the last time the subject was known to be event-free (censoring time). Use consistent units.
  • Data set columns: one per group. In the subject’s group column enter 1 if the event happened (death, relapse …) or 0 if the subject was censored (lost to follow-up, alive at the end of the study, withdrew). Leave the other groups blank on that row.
Censoring must be uninformative. Kaplan-Meier assumes that subjects who are censored have the same future risk as those still followed. Withdrawing because of side effects, for example, violates this assumption.

Parts of whole

Row titles hold category names and the column holds amounts (counts, areas, masses). Use Fraction of total to compute percentages, and graph as pie, donut, horizontal bars or a single stacked bar.

Multiple variables tables

The layout of a statistics package or a tidy spreadsheet: one row per subject (or observation), one column per variable. Variables can be continuous (age, BMI, concentration) or binary coded as 0/1 (sex, outcome, event). Row titles can hold subject IDs; they label points in scatter plots and PCA biplots.

Use this table type for multiple linear regression, logistic regression, Cox proportional hazards regression, principal component analysis and correlation matrices. Graph two variables against each other with the variable scatter plot, optionally coloured by a third.

Nested tables

Use a nested table when each group contains several subjects (animals, patients, cell-culture dishes, independent experiments) and each subject was measured several times (technical replicates, several cells per animal, several fields per slide).

  • Each data set is a group (e.g. Control, Treated).
  • Each subcolumn is one subject in that group (choose the number of subjects when creating the table).
  • Each row is a replicate measurement of that subject; subjects may have different numbers of replicates.

Analyze with the nested t test / nested ANOVA; graph with the Nested scatter, which shows each subject’s values in its own symbol, the subject means as large open symbols and the group mean as a line.

Entering & editing data

Typing and moving

Click a cell and start typing (the old value is replaced); F2, Enter or a double-click edits the current value instead. Enter confirms and moves down, Tab moves right, Esc cancels. Values that are not numbers are shown in red and are ignored by analyses. Commas used as thousands separators are accepted.

Selecting, copying and pasting

Drag over cells, or use Shift+click or Shift+arrows to select a block. Ctrl+C copies it as tab-separated text that pastes directly into Excel, Google Sheets or Word. Ctrl+V pastes a block copied from any spreadsheet starting at the selected cell; the table grows automatically. Delete clears the selection.

Rows and columns

  • Right-click a cell: insert row above/below, delete rows, insert a data set, sort by the column, exclude values.
  • Right-click a data set header: rename, set replicates, insert before/after, move left/right, delete.
  • Double-click a header to rename the data set (or the X column title).
  • Five empty rows are always kept at the bottom so you can continue typing.

Row titles

The first column holds row titles: group names in grouped/contingency/parts tables, and optional labels (subject IDs, sample names) in the others.

Replicates

In XY and grouped tables each data set can have several subcolumns (Y1, Y2 …) holding replicate values for the same X or the same cell. Set them when creating the table, for one data set via the header’s right-click menu, or for all data sets with Data → Set replicates for all data sets. Reducing the number of replicates deletes the values in the removed subcolumns (undo restores them).

Graphs show the mean (or median) of the replicates with error bars; analyses use each replicate value unless you choose to fit means.

Excluding values

Select one or more cells, right-click and choose Exclude / include value(s). Excluded values appear grey and struck through. They are ignored by every analysis and graph but remain in the table, so the decision is visible, documented and reversible. Choose the same command again to include them.

Exclude only with a reason decided before looking at the results (e.g. a documented technical failure). Removing inconvenient values biases the results; see Outliers.

Importing & exporting data

File → Import CSV / Excel creates a new table from a .csv, .tsv, .txt, .xlsx or .xls file. Choose the table type first:

Parametric or not?

Parametric tests (t tests, ANOVA) assume the data were sampled from Gaussian (normal) populations. They are robust to moderate departures, especially with larger and equal-sized groups. Choose a nonparametric test when the data are clearly skewed or ordinal (scores, ranks) and cannot be transformed, or when there are obvious outliers you cannot explain. Often a better option for skewed positive data (concentrations, titers) is to log-transform them and use a parametric test. Do not pick the test after seeing which one gives the smaller P value.

Paired or not?

See Paired vs. unpaired. Pairing must come from the design (same subject, matched pairs, same experiment day), not from the data.

Full screen, focus mode & small screens

OpenPrism works best with as much screen as possible. Click ⛶ Full screen at the top right (or press F11, or View → Full screen). The button then reads ⤡ Exit full screen, and a small Exit full screen button stays in the bottom-right corner; Esc also leaves full screen.

Focus mode (View → Focus mode, Ctrl+Shift+F) hides the navigator and toolbar so tables, graphs and layouts get the whole window — useful on laptops and when presenting. Menus, dialogs and pop-ups automatically fit inside short or narrow windows.

Command palette

Press Ctrl+Shift+P (or View → Command palette) and type a few letters of any command or analysis — “welch”, “export tiff”, “kappa”, “full screen” — then Enter. Analyses can also be found by what they are used for (e.g. “agreement”, “rhythm”).

Which test should I use? (guided)

Analysis → Which test should I use? (also the 🧭 toolbar button) lists research goals for the type of the current table. Type words describing your goal to filter, then click a test to open it with the right settings. Blue buttons are first choices when assumptions hold; grey buttons are the alternatives for non-Gaussian data, outliers or unequal SDs. The complete list is in the test finder below.

Number format (strict)

Numbers use the mathematical format: an optional sign, digits, a decimal point, and optionally an exponent — 12.5, -0.03, .5, 1.2e-6, 3E4. Commas, spaces and other characters are never interpreted: 1,5, 1,234.5, 1 000, 12% or inf are not numbers. Such cells are shaded red in the grid (hover for an explanation), a message appears when they are pasted, and every analysis reports how many cells it ignored and shows examples. This rule exists because spreadsheets in different countries write numbers differently, and silently guessing (reading 1,5 as 15 or as 1.5) would corrupt results. When pasting from a spreadsheet that uses decimal commas, change its number format (or the system locale) to a decimal point first. Cells are separated by tabs when pasting (as all spreadsheets copy them); CSV files are read with Import.

Calculated columns

Data → Add calculated column (formula) adds a data set computed from the others, row by row (and replicate by replicate): (B - A) / A * 100, log10(C), B / mean… Refer to data sets by their letters. Operators: + - * / ^ (with the usual precedence; -A^2 is −(A²)); functions log10, ln, log2, exp, sqrt, abs, round, floor, ceil, min, max, pow, logit, invlogit, sin, cos, tan; constants pi, e. A preview shows the first rows. The column recalculates whenever its inputs change; its cells cannot be typed over (right-click the column header to edit the formula or convert it to ordinary values). Formulas are evaluated by a small parser — they can never run code. Letters refer to positions: if you insert or delete data sets, check the formula.

Sharing projects with colleagues

File → Share a copy with a colleague sends a copy of the open project to another user of the same server. The copy is encrypted in your browser for your colleague's personal key, so the server — and its administrators — can neither read it nor redirect it. Your colleague finds it under File → Shared with me and saves it as their own project (re-encrypted with their own key); later changes are not synchronized, so share again to send an update. Pending shares can be withdrawn under File → Shares I sent.

Verifying keys. The share dialog shows the recipient's key fingerprint. For sensitive data, ask your colleague to read the fingerprint shown in their Account dialog and check that it matches. OpenPrism remembers the fingerprint and warns you if a colleague's key ever changes (which happens after a password reset without the recovery key — or would happen if someone tried to intercept). Administrators can turn sharing off in the admin console.

Cryptography. Each user has an ECDH P-256 key pair; the private key is stored on the server only encrypted with the user's data key. A share is encrypted with a fresh AES-256-GCM key, which is wrapped for the recipient with an ephemeral ECDH key agreement and HKDF-SHA256.

Toolbar, menus & keyboard

The toolbar adapts to the window: full (icon above label), compact (one slim row; only the main buttons keep their labels) or icons only, chosen automatically to fit; the ⇔ button at its right end (or View → Toolbar) fixes a size. Buttons that do not apply to the current item are hidden, and the Analyze group offers the quick tests that fit the current table type (e.g. t test and ANOVA for column tables, curve fit and linear regression for XY tables). Every button shows its keyboard shortcut in its tooltip.

Menus that do not fit the menu bar move into More ▾. Keyboard: F10 opens the first menu, ←/→ switch menus, ↑/↓ move, Enter runs, Esc closes.

Calculation activity & speed

The indicator in the top bar shows when work is going on — “⚙ Computing: One-way ANOVA · 0.4 s” with a spinner — and otherwise the duration of the last calculation. Click it (or View → Calculation activity log) for the log of this session: every analysis, import, export and graph summary with the time you waited, the time spent in the server's isolated calculation worker and the CPU time it used. Only names and timings are logged, never data.

Speed: graph summary values (means, SD, SEM, CIs, medians, IQRs) are calculated directly in your browser, so graphs redraw instantly; they are tested to agree with the server to 15 digits. Statistical tests run on the server, which loads all statistical libraries once at start-up so each calculation starts immediately (typically 5–30 ms). Large data tables (thousands of rows) only render the visible rows, so scrolling and editing stay fast.

Exchanging data with GraphPad Prism

File → Import CSV / Excel / GraphPad Prism reads Prism XML project files (.pzfx; in Prism use File → Save As and choose the .pzfx format). All data tables are imported with their type, replicate subcolumns, row titles, X values and excluded values; tables entered as summary data (mean with SD/SEM and N) are imported as their means, with a warning. Prism's analyses and graphs are recreated in OpenPrism from the data.

File → Export all data tables to GraphPad Prism (.pzfx) writes every data table to a .pzfx file that Prism opens, so colleagues who use Prism can continue with your data.

Shapes, templates & vector formats

Shapes on layouts: Add to page → Shapes adds lines, arrows (with heads at the end, start or both), rectangles, ellipses and significance brackets. Choose colour, fill, line width, dashes and direction in the inspector; shapes move and resize like any item and are exported as vectors. (Freehand drawing is intentionally not included.)

Images on layouts: Add to page → Add image places a PNG or JPEG (microscopy images, blots, photos, schematics) on the page. It moves and resizes like any item, keeps its proportions unless you choose Stretch, and is stored inside the encrypted project (very large images are downscaled to 3000 pixels, enough for 600 dpi at 5 inches). Images are included in every export format, including PDF, EPS and EMF.

Style templates: format a graph, click ★ Save as template, then apply it to any graph — or to all graphs of the same table type — from Templates…. Templates keep fonts, colours, symbols, axes and sizes, not titles or data. Use Export all… / Import… to share a lab or journal style as a small JSON file.

EPS and EMF: besides TIFF, PNG, JPEG, WEBP, PDF and SVG, graphs and layouts export as EPS (Encapsulated PostScript — Illustrator, CorelDRAW, LaTeX, printers) and EMF (Windows Enhanced Metafile — Word, PowerPoint, Visio). Both stay fully vector with editable text. These formats have no transparency, so semi-transparent fills (e.g. confidence bands) are blended with white and drawn beneath lines and symbols.

Reproducibility, all digits & methods text

Every result ends with a 🔁 Reproducible line: OpenPrism, NumPy, SciPy and statsmodels versions and a SHA-256 fingerprint of the analysed data. The same data and settings always give bit-identical results — resampling methods (bootstrap, permutation and Monte-Carlo exact tests, k-means) use fixed seeds.

All digits in the results header shows every significant digit (15–17) instead of rounded values — useful for checking against other software. 📝 Methods produces a paragraph for the methods section of a paper with the test, its settings, the software versions and the data fingerprint.

Numerical care built in: values with a large constant part (e.g. 1 000 000 000 000.4) are centred in exact decimal arithmetic before analysis; polynomial and ill-conditioned regressions are solved from the exact decimal data in 80-digit arithmetic; the curve fitter tries several algorithms and keeps the best fit.

Validation of results

OpenPrism's statistics are checked automatically against (1) NIST Statistical Reference Datasets with certified values, (2) R and established CRAN packages (survival, MASS, metafor, psych, car, lmtest, quantreg, circular, nlme, coin), (3) Monte-Carlo calibration of type I error and confidence-interval coverage and (4) reproducibility and invariance tests — about 700 checks. See the validation report (also under Help) for every value, the number of correct digits (LRE) and the problems the suite found and that were fixed. Anyone can rerun it: python validation/run_validation.py.

Still validate for regulated work. No validation suite covers every situation. For regulated (GLP/GMP, clinical) use, validate the analyses you rely on against your reference software and keep the validation report with your records.

Analysis reference

One card per analysis, in the same format: what it does, when to use it, how to lay out the data, how to run it, how to read the results, assumptions, alternatives and key references. The same text appears in each analysis dialog under About this analysis. Detailed chapters, where available, are linked from the card.

Descriptive statistics

Table types: XY, Column, Grouped, Contingency, Survival, Parts of whole, Multiple variables, Nested · menu: Analysis → Descriptive statistics Detailed chapter →

What it doesSummarizes each data set: number of values, mean, SD, SEM, confidence interval of the mean, median with its confidence interval, quartiles, range, coefficient of variation, geometric mean and SD factor, skewness and kurtosis.
When to use itAlways — before any test, to know your data. Use it to report n, central tendency and spread, and to spot entry errors (impossible minima/maxima).
Data layoutColumn table: one data set per column (replicates as rows). Also works on XY, grouped and multiple-variables tables.
How to run itChoose the data sets and the confidence level. Results update automatically when values change.
Reading the resultsReport mean ± SD to describe variability of individuals; mean ± SEM or a 95% CI to describe how precisely the mean is known. For skewed data report the median and quartiles (or the geometric mean and geometric SD factor for log-normal data).
AssumptionsNone for the numbers themselves. The CI of the mean assumes approximately Gaussian data or a large sample; the CI of the median is distribution-free.
AlternativesFrequency distribution (histogram) to see the shape; normality tests; bootstrap CIs for any statistic.
ReferencesAltman & Bland (2005) BMJ 331:903 (SD vs SEM).

Normality and lognormality tests (with Q-Q plot)

Table types: Column, XY, Grouped, Multiple variables, Nested · menu: Analysis → Normality and lognormality tests (with Q-Q plot) Detailed chapter →

What it doesTests whether values plausibly come from a Gaussian (normal) distribution: Shapiro-Wilk, D'Agostino-Pearson omnibus (skewness + kurtosis), Kolmogorov-Smirnov with the Lilliefors correction, Anderson-Darling, Jarque-Bera and Shapiro-Francia; optionally the same tests on log-transformed values (lognormality). A Q-Q plot is drawn.
When to use itBefore choosing between a parametric test (t test, ANOVA) and a nonparametric one, or to check residuals of a model.
Data layoutColumn table (one data set per column); also XY/grouped/multi tables.
How to run itPick the tests (Shapiro-Wilk is the best general choice for n ≤ 5000; D'Agostino-Pearson needs n ≥ 8). Tick 'lognormal' when values are positive and skewed.
Reading the results'Passed' (P ≥ α) means there is no evidence against normality — not proof of normality. With small n the tests have little power; with very large n they flag trivial departures. Always look at the Q-Q plot: points close to the line mean near-Gaussian data.
AssumptionsIndependent values.
AlternativesIf clearly non-Gaussian: transform (log), use a nonparametric test, a robust test (trimmed means) or a GLM with a suitable distribution.
ReferencesShapiro & Wilk (1965) Biometrika 52:591; D'Agostino et al. (1990) Am Stat 44:316.

t tests (and nonparametric tests)

Table types: Column · menu: Analysis → t tests (and nonparametric tests) Detailed chapter →

What it doesCompares two groups: unpaired t test (optionally with Welch's correction for unequal SDs), paired t test, Mann-Whitney test or Wilcoxon matched-pairs signed-rank test. Reports the difference with its CI, Cohen's d, Hedges' g with CI, a Bayes factor and, for unpaired data, an F test of equal variances. Mann-Whitney and Wilcoxon P values are exact (also with ties) up to n = 50.
When to use itIs the mean (or distribution) of group B different from group A? Treated vs control; before vs after on the same subjects (paired).
Data layoutColumn table with two data sets (A and B). For paired data, values on the same row belong to the same subject.
How to run itChoose paired/unpaired, parametric/nonparametric; consider Welch's correction (recommended by default when group SDs or sizes differ); choose one- or two-tailed P values (two-tailed unless the direction was fixed before seeing the data).
Reading the resultsReport the difference with its 95% CI and the P value. The CI shows the size and precision of the effect; a P value alone does not.
AssumptionsIndependent observations (or independent pairs). t tests: Gaussian populations (or differences, if paired); Student's t also equal SDs. Mann-Whitney: tests whether one group tends to have larger values; it compares medians only if the shapes are equal.
AlternativesWelch t (unequal SDs); Yuen trimmed-means test (outliers, heavy tails); Brunner-Munzel (unequal shapes); permutation test; equivalence test (TOST) to show similarity; Bayesian t test for evidence for H0.
ReferencesDelacre, Lakens & Leys (2017) Int Rev Soc Psychol 30:92 (use Welch by default).

One-way ANOVA (and nonparametric or mixed)

Table types: Column · menu: Analysis → One-way ANOVA (and nonparametric or mixed) Detailed chapter →

What it doesOne-way ANOVA (ordinary, Welch, Brown-Forsythe, repeated measures with Geisser-Greenhouse correction or a mixed model) or the nonparametric Kruskal-Wallis / Friedman tests, followed by multiple comparisons (Tukey, Dunnett, Šídák, Holm-Šídák, Bonferroni, Fisher LSD, FDR, Games-Howell, Dunnett T3, Tamhane T2, Dunn).
When to use itDo three or more group means differ? Which groups differ from which (or from a control)?
Data layoutColumn table, one group per column. For repeated measures, each row is one subject measured under every condition.
How to run itChoose matching (repeated measures), Gaussian vs nonparametric, then the multiple-comparison method: Tukey for all pairs, Dunnett vs a control, Games-Howell/T3 if SDs differ.
Reading the resultsThe overall F test asks whether any means differ; multiple comparisons tell which. Report adjusted P values and simultaneous CIs of differences.
AssumptionsIndependent groups (or independent subjects); Gaussian residuals; equal SDs for ordinary ANOVA (check the Brown-Forsythe test, or use Welch ANOVA); sphericity for repeated measures (use the Geisser-Greenhouse correction).
AlternativesWelch ANOVA + Games-Howell (unequal SDs); robust trimmed-means ANOVA; Kruskal-Wallis + Dunn; mixed model when repeated-measures data have missing values; test for trend for ordered groups.
ReferencesMaxwell, Delaney & Kelley (2018) Designing Experiments and Analyzing Data, 3rd ed.

Identify outliers

Table types: Column, Multiple variables · menu: Analysis → Identify outliers Detailed chapter →

What it doesIdentifies outliers by Grubbs' test (one or iteratively several), generalized ESD (Rosner; several outliers at once, avoids masking), ROUT-like robust detection (median/MAD with FDR control), Tukey's IQR fences or the Hampel filter (median ± t·MAD); writes a cleaned copy of the data.
When to use itWhen a value might be a technical error. Never remove a value only because it is inconvenient — record and justify every exclusion.
Data layoutColumn table (or multiple-variables table).

AlternativesRobust methods (trimmed means, rank tests, robust regression) that are insensitive to outliers instead of removing them.

Compare variances (F, Levene, Brown-Forsythe, Bartlett, Fligner-Killeen)

Table types: Column · menu: Analysis → Compare variances (F, Levene, Brown-Forsythe, Bartlett, Fligner-Killeen)

What it doesTests whether groups have equal variances (SDs): F test (two groups, with CI of the ratio), Levene, Brown-Forsythe (median-centred Levene), Bartlett, Fligner-Killeen, and for two groups the Ansari-Bradley and Mood scale tests.
When to use itWhen the variability itself is of interest (precision of two methods, heterogeneity of responses), or to decide on Welch's correction.
Data layoutColumn table, one group per column.
How to run itSelect the groups. The Brown-Forsythe test is the recommended general-purpose test.
Reading the resultsP < α: the SDs differ. Do not use these tests as a gate before a t test — use Welch's t test routinely instead.
AssumptionsF and Bartlett: Gaussian data (very sensitive to non-normality). Levene/Brown-Forsythe: robust. Fligner-Killeen, Ansari-Bradley, Mood: nonparametric; Ansari-Bradley and Mood assume equal medians.
AlternativesWelch t test / Welch ANOVA when SDs differ; transform data (log) when SD grows with the mean.
ReferencesBrown & Forsythe (1974) JASA 69:364; Conover, Johnson & Johnson (1981) Technometrics 23:351.

Compare distributions (KS, Cramér-von Mises, Anderson-Darling, Brunner-Munzel…)

Table types: Column · menu: Analysis → Compare distributions (KS, Cramér-von Mises, Anderson-Darling, Brunner-Munzel…)

What it doesTests whether groups come from the same distribution (any difference in location, spread or shape): Kolmogorov-Smirnov, Cramér-von Mises, Epps-Singleton, Brunner-Munzel and Mann-Whitney (two groups); Anderson-Darling k-sample (permutation P) and Mood's median test (any number of groups), with Holm-adjusted pairwise KS tests.
When to use itWhen the question is 'do the distributions differ?' rather than 'do the means differ?', e.g. comparing cell-size distributions, reaction-time distributions or particle-size spectra.
Data layoutColumn table, one group per column.
How to run itSelect two or more groups. Permutation P values use 9 999 resamples with a fixed seed (reproducible).
Reading the resultsKS is most sensitive in the middle of the distributions; Anderson-Darling and Cramér-von Mises also detect differences in the tails. Brunner-Munzel tests P(X < Y) = ½ even when shapes differ.
AssumptionsIndependent observations. KS P values are exact for small samples without ties.
Alternativest test / Mann-Whitney for location only; compare variances for spread only.
ReferencesScholz & Stephens (1987) JASA 82:918; Brunner & Munzel (2000) Biom J 42:17.

Robust comparison of trimmed means (Yuen, Wilcox)

Table types: Column · menu: Analysis → Robust comparison of trimmed means (Yuen, Wilcox)

Test for trend across ordered groups (linear trend, Jonckheere-Terpstra)

Nonparametric multiple comparisons (Dunn, Conover, DSCF)

Table types: Column · menu: Analysis → Nonparametric multiple comparisons (Dunn, Conover, DSCF)

What it doesNonparametric multiple comparisons after a Kruskal-Wallis test: Dunn's test, Conover-Iman, Dwass-Steel-Critchlow-Fligner (pairwise ranking, family-wise error built in) or pairwise Mann-Whitney tests, with Holm, Bonferroni, Hochberg or FDR adjustment.
When to use itWhich groups differ when the data are not Gaussian?
Data layoutColumn table, three or more groups.

AlternativesRobust trimmed-means comparisons; Games-Howell after a Welch ANOVA.

Reading results

A result sheet starts with the title of the test and a line summarizing the data and options. Warnings (yellow boxes) flag problems such as small expected counts, ambiguous curve fits or multicollinearity — read them. The following sections contain:

  • Summary tables: the P value, its summary in asterisks, and whether it is below alpha.
  • Effect sizes: mean differences with confidence intervals, R², odds ratios, hazard ratios … These tell you how big an effect is, which matters more than whether it is “significant”.
  • Detailed tables: ANOVA tables, multiple comparisons, parameter estimates.

P values & significance

A P value answers: if the null hypothesis were true (no difference, no association), how likely would a result at least this extreme be, by chance?

  • A small P value means the data would be surprising under the null hypothesis. It does not give the probability that the null hypothesis is true, nor the size or importance of the effect.
  • A large P value does not prove there is no effect — the experiment may simply have too little power. Look at the confidence interval: if it includes both zero and biologically important values, the experiment is inconclusive.
  • Run the tests you planned. Running many tests and reporting only the significant ones inflates false positives; use multiple-comparison corrections.
  • Two-tailed P values are the default and almost always appropriate. Use one-tailed only when the direction was predicted before collecting data and an effect in the other direction would be treated as no effect.

Alpha (significance level)

Alpha is the threshold for calling a P value “statistically significant” — the false-positive rate you accept when the null hypothesis is true. 0.05 is conventional; 0.01 is stricter. Alpha also sets the confidence level of reported intervals (α = 0.05 → 95% CI) and the critical values used for multiple comparisons. Choose alpha before the experiment.

Descriptive statistics

For each data set: number of values, minimum, 25th percentile, median, 75th percentile, maximum, range, 95% CI of the median, mean, SD, SEM, 95% CI of the mean, coefficient of variation, geometric mean and geometric SD factor, skewness, kurtosis and sum.

  • SD describes the scatter of the values. SEM = SD/√n describes how precisely the mean is determined; it shrinks with larger n. Use SD to describe variability, a CI to describe precision.
  • CV = SD/mean × 100%, meaningful only for ratio-scale data (true zero).
  • Geometric mean (antilog of the mean of logs) suits lognormal data such as concentrations and titers; the geometric SD factor is a multiplicative spread (values range from mean/factor to mean×factor).
  • Skewness > 0 means a long right tail; kurtosis (excess) > 0 means heavier tails than a Gaussian distribution.
  • Quartiles use the n+1 (Weibull) method; the median CI uses the binomial order-statistic method.

Normality tests & Q-Q plots

Tests whether each data set is consistent with sampling from a Gaussian distribution:

  • Shapiro-Wilk — recommended for most sample sizes (n ≥ 3).
  • D’Agostino-Pearson omnibus — combines skewness and kurtosis; needs n ≥ 8.
  • Kolmogorov-Smirnov with Lilliefors correction — less powerful; included for completeness.
  • Anderson-Darling — sensitive to the tails.

Tick Also test for lognormal distribution to test the log of the values as well. A Q-Q plot (actual values against those expected from a normal distribution) is produced as an analysis plot: points close to the line of identity indicate approximately Gaussian data; a curved pattern indicates skew; S-shapes indicate heavy or light tails.

“Passed” is not proof. With small samples normality tests have little power and almost always pass; with very large samples trivial deviations are “significant”. Use them together with the Q-Q plot and knowledge of the kind of data.

Paired vs. unpaired designs

Use a paired (or repeated-measures) test when the values in different groups are linked by design: the same subject measured before and after treatment, the same cell culture split into control and treated wells, twins, or control and treated samples processed on the same day. Pairing removes the variability between subjects, often greatly increasing power. Enter matched values on the same row.

The paired t test result reports the correlation between the paired values (“How effective was the pairing?”). A strong positive correlation means pairing was helpful.

Parametric vs. nonparametric tests

Parametric tests compare means and assume Gaussian populations (and, for ordinary ANOVA and Student’s t, equal SDs). Nonparametric tests rank the data and make fewer assumptions, but:

  • they have less power, especially with small samples (with n = 3 per group a Mann-Whitney test can never give P < 0.05 two-tailed);
  • they do not give confidence intervals for differences between means;
  • they test whether distributions differ, which equals a test of medians only if the distributions have the same shape.

Welch correction

Student’s t test and ordinary ANOVA assume all groups have the same population SD. Welch’s versions do not; they adjust the degrees of freedom. Welch’s t test loses very little power when SDs are equal and protects against false positives when they are not, particularly with unequal group sizes. For one-way ANOVA, tick Also report Welch’s ANOVA.

One-way ANOVA and nonparametric alternatives

Tests whether the means of three or more groups differ.

  • Ordinary one-way ANOVA: F test of between-group vs within-group variance; reports R² and the ANOVA table. Brown-Forsythe and Bartlett’s tests check equality of SDs.
  • Welch’s ANOVA: does not assume equal SDs.
  • Repeated-measures one-way ANOVA: each row is a subject measured under every condition (rows with missing values are excluded). Reports whether matching was effective and the Geisser-Greenhouse epsilon (see sphericity).
  • Kruskal-Wallis (nonparametric, independent groups) with Dunn’s multiple comparisons on mean ranks.
  • Friedman (nonparametric, matched rows) with Dunn’s comparisons on rank sums.

The overall ANOVA P value tells you whether there is evidence that some means differ. Use multiple comparisons to find out which.

Repeated measures & sphericity

Repeated-measures ANOVA assumes sphericity: the variance of the differences between every pair of conditions is the same. This is often violated (e.g. measurements closer in time are more correlated). The Geisser-Greenhouse correction multiplies both degrees of freedom by epsilon (ε, between 1/(k−1) and 1); ε = 1 means perfect sphericity. Leaving the correction on is the safe default.

Two-way ANOVA

For grouped tables. Tests three hypotheses:

  • Interaction — does the effect of one factor depend on the level of the other? (Requires replicates.) If the interaction is significant, interpret the main effects with care.
  • Row factor — do the rows differ, averaging over columns?
  • Column factor — do the data sets differ, averaging over rows?

OpenPrism fits the linear model with sum-to-zero contrasts and reports Type III sums of squares, which remain valid for unbalanced designs. The table shows the percentage of total variation explained by each source. Multiple comparisons compare columns within each row (default) or rows within each column using the pooled error term; with Šídák, Bonferroni or Holm the family is all comparisons across all rows.

Without replicates (one value per cell) the interaction cannot be separated from error and a main-effects model is fitted (a warning is shown).

Mixed-effects models

A mixed-effects model contains fixed effects — the treatments or conditions you want to compare — and random effects — the variability between subjects (or experiments, litters, plates) that must be accounted for. OpenPrism uses a random intercept per subject and fits the model by restricted maximum likelihood (REML, statsmodels).

  • Missing values: a subject with one missing measurement is kept; repeated-measures ANOVA must drop the whole subject.
  • Unbalanced designs and unequal numbers of replicates are handled naturally.
  • The intraclass correlation (ICC) shows how much of the variability lies between subjects.

Fixed effects are tested with Wald chi-square tests (also shown as “F = χ²/DF”). Multiple comparisons use model estimates and standard errors with residual degrees of freedom; with few subjects these P values are approximate.

Nested t test and nested one-way ANOVA

Treating every technical replicate as an independent observation (pseudoreplication) makes P values far too small. The nested analysis fits a mixed-effects model with groups as fixed effect and subjects as random effect, so the subject is the experimental unit.

  • Two groups: nested t test — difference with CI and P value (degrees of freedom = subjects − groups).
  • Three or more groups: nested one-way ANOVA (Wald test) with multiple comparisons.
  • Variance components (SD between and within subjects, intraclass correlation) and subject means.

With balanced data the nested t test equals an ordinary t test on the subject means.

Multiple t tests

Runs one unpaired t test (optionally Welch) per row of a grouped table comparing the first two data sets — e.g. one test per gene or per time point — and corrects the P values for multiple testing (Holm-Šídák, Bonferroni, or the Benjamini-Hochberg false discovery rate).

Identifying outliers

  • Grubbs’ test: assumes the other values are Gaussian; removes the most extreme value if significant and repeats (iterative).
  • ROUT-like robust method: standardizes each value by the median and the median absolute deviation (robust to the outliers themselves) and controls the false discovery rate Q (1% is typical). It can find several outliers at once.
  • Tukey fences: values more than k × IQR (default 1.5) beyond the quartiles.

The result lists the outliers and creates a Cleaned data table without them.

Think before removing. An outlier may be a mistake (then fix or exclude it with a documented reason), or real biological variability (then keep it, or use robust/nonparametric methods). Report how outliers were handled.

Frequency distributions (histograms)

Counts how many values fall in each bin. Leave the bin width blank for an automatic choice (Sturges’ rule). Tabulate counts, percentages or fractions, optionally cumulative. The output XY table can be graphed with Area fill or as bars.

ROC curves

Evaluates how well a continuous marker discriminates patients from controls. The first ticked data set is the controls, the second the patients; choose whether patients have higher or lower values.

  • AUC (area under the curve) = probability that a randomly chosen patient has a more abnormal value than a randomly chosen control. 0.5 = no discrimination, 1.0 = perfect. Its SE uses the Hanley-McNeil method.
  • The sensitivity/specificity table lists every possible cutoff with the likelihood ratio; choose the cutoff according to the clinical cost of false positives and false negatives.

Bland-Altman method comparison

Assesses agreement between two methods measuring the same quantity (enter paired measurements on the same row; first data set = method A, second = method B). Correlation is not a measure of agreement — two methods can be perfectly correlated yet disagree systematically.

  • Bias: mean difference (A − B), with its 95% CI. A CI excluding 0 indicates a systematic difference.
  • 95% limits of agreement: bias ± 1.96 SD of the differences — the range containing 95% of differences between methods for an individual sample. Whether this is acceptable is a clinical/scientific judgement.
  • Proportional bias: slope of difference vs average; if significant, the disagreement grows with the magnitude — plot the ratio or % difference instead.

The Bland-Altman plot (difference vs average with bias and limit lines) is created as an analysis plot.

Equivalence test (TOST)

A non-significant difference does not show that two treatments are equivalent. Enter the smallest difference that would matter as lower and upper margins (chosen before the experiment). Two one-sided Welch t tests check that the difference lies above the lower and below the upper margin; equivalence is shown when both are significant — equivalently, when the 90% CI (α = 0.05) lies inside the margins.

Bayesian t test

Reports the JZS Bayes factor (Rouder et al. 2009) with a Cauchy prior on the effect size (scale r = 0.707). BF10 is how many times more likely the data are under “a difference” than under “no difference”: 1–3 anecdotal, 3–10 moderate, 10–30 strong, 30–100 very strong, >100 extreme; reciprocal values grade the evidence for no difference. Ordinary t test results include BF10 and Hedges’ g with CI too.

Bootstrap confidence intervals

Resamples each data set with replacement thousands of times and reports percentile confidence intervals for the mean, median or SD and, for two data sets, for their difference. Useful for medians and skewed data. Results are reproducible (fixed seed).

Permutation test

Re-assigns the group labels in every possible way (exact when there are at most 20 000 arrangements, otherwise 20 000 random permutations) and counts how often a difference at least as large as observed arises. Choose the difference of means or medians. No distributional assumption is needed.

Contingency tables (chi-square & Fisher’s exact)

  • Fisher’s exact test (2×2): exact P value; preferred for 2×2 tables, especially with small counts.
  • Chi-square test: for larger tables, or 2×2 with large counts. Optional Yates continuity correction for 2×2. A warning appears when expected counts are below 5.
  • Chi-square for trend: for tables with ordered rows (e.g. dose groups) and two outcome columns.
  • Effect sizes (2×2): odds ratio (Woolf CI), relative risk (Katz CI), attributable risk, number needed to treat/harm, sensitivity, specificity, positive and negative predictive values; Cramér’s V for any table.

Use the relative risk for prospective/cohort studies and randomized trials; use the odds ratio for case-control studies.

Survival analysis

Computes Kaplan-Meier survival curves for each group: at every event time the survival fraction is multiplied by (1 − deaths/at risk). The tables list number at risk, events, survival % and the 95% CI (Greenwood variance, log-log transformation, so limits stay between 0 and 100%).

  • Median survival: the time at which survival first drops to 50% or below (“undefined” if it never does).
  • Log-rank (Mantel-Cox) test: compares whole curves, giving equal weight to all time points; most powerful when hazards are proportional.
  • Gehan-Breslow-Wilcoxon test: weights early events more heavily.
  • Hazard ratio (two groups): logrank estimate (O₁/E₁)/(O₂/E₂) with 95% CI. HR = 2 means the first group’s event rate is twice that of the second at any time.
  • With three or more groups, pairwise log-rank comparisons with Bonferroni correction are listed.

The survival graph is a staircase with tick marks for censored subjects and optional confidence bands. To adjust for covariates (age, stage…), enter one row per subject in a multiple variables table and use Cox regression.

Fraction of total

Lists each category’s value, fraction and percent of the total. Optionally runs a chi-square goodness-of-fit test against equal proportions — appropriate only when the values are counts.

Nonlinear regression (curve fitting)

Finds the parameter values of an equation that minimize the sum of squared vertical distances between the curve and the points (Levenberg-Marquardt / trust-region least squares). Each data set is fitted separately unless you use global fitting.

Results

  • Best-fit values of each parameter, plus derived values: EC50/IC50 from log parameters, half-life and τ for exponentials, doubling time for growth.
  • Std. Error and 95% CI (asymptotic, from the covariance matrix). Wide CIs mean the data do not define the parameter well.
  • Goodness of fit: degrees of freedom, R², sum of squares, Sy.x (SD of the residuals), AICc and the number of points.
  • Normality of residuals (Shapiro-Wilk).
  • Optional interpolation, model comparison and residual table.
Ambiguous fits. If parameters are so intertwined that the data cannot determine them (dependency > 0.9999, e.g. a sigmoid without a top plateau), a warning is shown. Constrain a parameter (e.g. Top = 100 for normalized data), collect data over a wider X range, or choose a simpler model.

Tick Plot confidence band to draw the 95% confidence band of the curve on the graph. The curve is drawn on every graph of the table that is linked to the analysis.

User-defined equations

Choose Write your own equation… at the bottom of the equation list. Write one statement per line (or separate with ;). Intermediate variables may be defined; the last line must define Y. Example:

Span = Top - Bottom
Y = Bottom + Span/(1 + 10^((LogEC50 - X)*HillSlope))
  • X (capital) is the independent variable. Every other name that is not a function, a constant or an intermediate variable becomes a fitted parameter.
  • Operators: + - * /, ^ (power), %, parentheses. Conditional: A if X < X0 else B.
  • Functions: exp, ln, log, log10, log2, sqrt, abs, sin, cos, tan, atan, arctan, sinh, cosh, tanh, erf, min, max, pow. Constants: pi, e.
  • Initial values: e.g. Top=100, Bottom=0, LogEC50=-7, HillSlope=1. Parameters named Top/Plateau/Vmax/Bmax/Amplitude start at the largest Y, Bottom/Baseline/Y0 at the smallest, others at 1. Good initial values matter for complex models.
  • Constraints: enter Bottom=0, HillSlope=1 to fix parameters to constants.

Equations are parsed and evaluated by a restricted interpreter: only arithmetic and the listed functions are allowed, so an equation can never execute other code on the server.

Constraints & initial values

Fixing a parameter to a constant reduces the number of parameters to fit, which is often essential with limited data. Typical constraints: Bottom = 0 when background is subtracted; Top = 100 and Bottom = 0 for normalized dose-response data; HillSlope = 1 for simple binding; Plateau = 0 for complete decay. Leave a box empty to fit the parameter.

Global fitting (shared parameters)

Global fitting fits all selected data sets simultaneously, with some parameters shared (one value for all data sets) and others fitted separately. For example, for a family of dose-response curves you may share Bottom, Top and HillSlope and fit an individual LogEC50 for each curve. Sharing uses all the data to estimate the shared parameters, making the individual parameters much more precise.

Tick the parameters to share under Global fit. The result adds:

  • A table of the global best-fit values and standard errors (shared parameters are labelled “(shared)”) and CIs of the shared parameters.
  • Do the shared parameters differ between data sets? — an extra sum-of-squares F test comparing the global model (shared) with separate fits. A small P value means a single shared value is not consistent with the data.

The curves on the graph are drawn from the global fit.

Profile-likelihood confidence intervals

Tick Also compute profile-likelihood confidence intervals in the nonlinear regression dialog. For each parameter, OpenPrism fixes it at trial values on both sides of the best-fit value, refits all other parameters, and finds the values at which the sum of squares reaches

SS = SSmin × (1 + F(α; 1, df) / df)

— the extra-sum-of-squares criterion. Unlike the usual asymptotic intervals (best fit ± t × SE), profile intervals follow the actual shape of the fit and are often asymmetric, which is more accurate for parameters such as EC50, Km, rate constants or Hill slopes. When the data never make the fit significantly worse in one direction, that limit is reported as unbounded: the data do not define it (collect data over a wider range or constrain a parameter). For straight lines the profile interval equals the exact t interval.

Weighting

Ordinary least squares assumes the scatter of points around the curve (SD) is the same everywhere. In many assays the scatter grows with Y (e.g. constant CV). Then use relative weighting (1/Y²), which minimizes the sum of squared relative distances. Use Poisson weighting (1/Y) for counts (radioactivity, cell counts). Look at the residuals: a funnel shape suggests weighting is needed.

Interpolating unknowns from a standard curve

Enter Y values (e.g. absorbances of unknown samples) separated by commas. OpenPrism solves the fitted equation for X at each value, searching first within the range of the standards and rejecting spurious solutions. Values outside the curve are reported as “Out of range”. Prefer standards that bracket all unknowns — extrapolation is unreliable.

Comparing models

Select an alternative equation under Compare with alternative model. For each data set both models are fitted and compared:

  • Extra sum-of-squares F test — valid for nested models (one is a special case of the other, e.g. 3- vs 4-parameter dose-response, one- vs two-phase decay). A small P value favors the more complex model.
  • AICc (Akaike’s information criterion, corrected for small samples) — works for any two models; reported as the probability that the more complex model is correct.

ROUT robust fitting and outlier removal

Tick Robust fit & remove outliers (ROUT) in nonlinear regression. Following Motulsky & Brown (2006), the model is first fitted with a robust Lorentzian (Cauchy) loss, the robust SD of the residuals (RSDR) is computed, points whose residuals are significant at false discovery rate Q (1% recommended) are flagged, and the remaining points are fitted by least squares. Removed points are listed in the results.

Linear regression

Fits Y = slope·X + intercept to each data set (optionally forced through the origin). Reports slope and intercepts with SE and CI, R², Sy.x, an F test of whether the slope differs from zero, and a runs test (few runs → the data systematically deviate from a straight line; consider a nonlinear model).

With two or more data sets, OpenPrism tests whether the slopes are equal (ANCOVA-style F test). If they are not significantly different, it tests whether the intercepts (elevations) are equal and reports the pooled slope.

Tick Plot confidence bands to show the 95% CI of the line, and show the equation on the graph.

Deming regression

Ordinary regression assumes X has no error. When comparing two measurement methods, both have errors; Deming regression accounts for that. Enter method 1 as X and method 2 as Y, and the ratio of the error SDs (1 = equally precise, orthogonal regression). CIs by jackknife. Agreement: slope CI includes 1 and intercept CI includes 0.

Passing-Bablok regression

Nonparametric method-comparison regression: the slope is the shifted median of all pairwise slopes, the intercept the median of Y − slope·X; robust to outliers and non-normal errors (Passing & Bablok 1983).

Correlation

Pearson r quantifies linear association assuming bivariate Gaussian data; Spearman r uses ranks and detects any monotonic association. Each pair reports r, its 95% CI (Fisher z), R², P value and the number of pairs. On an XY table, X is correlated with each data set; tick full correlation matrix (or use a column / multiple variables table) to correlate every pair. A colour-coded correlation-matrix heat map is available as an analysis plot.

Correlation is not causation, and a significant r can be small and unimportant with large samples. Do not use correlation to assess agreement between methods (use Bland-Altman).

Area under the curve

Computes the area between the curve (mean Y of each row) and a baseline with the trapezoid rule. The SE of the area is computed from the SEM of each point (Gagnon & Peterson), giving a 95% CI. Also reported: total peak area above the baseline, number of peaks, and the X and Y of the highest point.

Smooth, differentiate or integrate

  • LOWESS: locally weighted regression; the span is the fraction of points used for each local fit (larger = smoother). The smooth curve is drawn on the graph.
  • Moving average over a window of points.
  • Derivative: dY/dX by central differences — e.g. rates from cumulative data.
  • Integral: cumulative area (trapezoid rule) from the first X.

Every operation also creates a new XY table with the results.

Multiple linear regression

Models a continuous dependent variable as a linear combination of several independent variables: Y = β₀ + β₁X₁ + β₂X₂ + …. Choose the dependent variable and tick the independent variables. Rows with a missing value in any chosen variable are skipped (and counted).

  • Parameter estimates: each β is the change in Y per unit change of that variable holding the others constant, with SE, CI, |t| and P.
  • VIF (variance inflation factor): > 5–10 indicates multicollinearity — predictors are so correlated that their individual effects cannot be separated.
  • Goodness of fit: R², adjusted R² (penalized for the number of predictors), Sy.x, AICc; an overall F test of the model against the intercept only.
  • Plots: actual vs predicted, residuals vs predicted (look for patterns or funnels) and a Q-Q plot of residuals.

Rule of thumb: have at least 10–20 observations per predictor.

Multiple logistic regression

Models the probability of a binary outcome (coded 1/0) from one or more predictors: logit(P) = β₀ + β₁X₁ + …. Coefficients are reported as odds ratios per one-unit increase in each predictor (OR > 1: higher odds of the outcome), with CIs and Wald P values.

  • Goodness of fit: Tjur’s R² (difference in mean predicted probability between 1s and 0s), McFadden pseudo R², log likelihood, AIC, likelihood-ratio test vs the intercept-only model, and the area under the ROC curve.
  • A classification table at the chosen cutoff (default 0.5).
  • Plots: fitted probability curve (single predictor), ROC curve, and a forest plot of odds ratios.

“Perfect separation” (a predictor that perfectly predicts the outcome) prevents the model from converging. Aim for at least 10 events per predictor.

Cox proportional hazards regression

Models the hazard (instantaneous event rate) as a function of covariates without assuming a shape for the baseline survival curve. In a multiple variables table choose the time variable, the event variable (1 = event, 0 = censored) and the covariates (continuous or 0/1 group indicators).

  • Hazard ratios per unit increase of each covariate with CI and P. HR = 1.05 for age means 5% higher hazard per year.
  • Likelihood-ratio test of the whole model and Harrell’s concordance index (C; 0.5 = no discrimination, 1 = perfect).
  • A forest plot of hazard ratios.

Ties are handled with Efron’s method. The model assumes hazards are proportional over time; check by plotting Kaplan-Meier curves (curves that cross suggest a violation).

Principal component analysis (PCA)

Transforms correlated variables into uncorrelated principal components (PCs), ordered by the variance they explain. Use it to explore structure in multivariable data, find groups of correlated variables, and reduce dimensionality.

  • Standardize (recommended when variables have different units/scales) analyzes the correlation matrix; center only analyzes the covariance matrix.
  • Eigenvalues and % of variance per component, with cumulative %.
  • Loadings: correlations between each variable and each component — which variables “make up” a component.
  • How many components? Kaiser rule (eigenvalue > 1), parallel analysis (components whose eigenvalue exceeds the 95th percentile from random data of the same size — usually the most reliable), and the number needed for 80% of variance.
  • Scores of every row on every PC are written to a new multiple variables table, so you can graph them or use them in further analyses.
  • Plots: scree plot with parallel analysis, biplot (scores plus loading arrows) and loadings plot.

Poisson regression

For counts (colonies, lesions, events) in a multiple-variables table. Coefficients are reported as rate ratios with CIs. The dispersion statistic (Pearson χ²/df) should be near 1; much larger values indicate over-dispersion.

Transform

Creates a new table in which every Y value (and optionally X) is transformed: log10, ln, 10^Y, e^Y, √Y, Y², 1/Y, |Y|, Y×K, Y+K, logit, or Z score within each data set. Values for which the transform is undefined (e.g. log of 0) become blank. Logarithmic transforms often make skewed positive data (concentrations, titers, fold changes) Gaussian.

Normalize

Rescales each data set to percent (or fraction): 0% is the smallest mean, the first value, or a value you enter; 100% is the largest mean, the last value, or a value you enter. Common before fitting normalized dose-response curves.

Remove baseline

Subtracts the first row of each data set from every value (e.g. time 0), or subtracts data set A from all other data sets row by row (e.g. a blank or non-specific binding column).

Transpose

Creates a table in which rows become data sets and data sets become rows (row titles become data set names). Replicates are averaged.

Accounts & privacy

OpenPrism is a multi-user server with end-to-end encryption: your projects are encrypted in your browser before they reach the server, and only you can decrypt them.

  • Create account on the sign-in page (if self-registration is allowed; otherwise the administrator creates it and gives you a one-time password). You receive a recovery key — store it safely.
  • Sign in: your password is turned into two keys in the browser; one proves who you are to the server, the other unlocks your data and never leaves the browser. The server never sees your password.
  • Unlock: on a new device or after clearing browser data, enter your password once to unlock your data key in that browser.
  • Change password in Account → My account; your data key is re-wrapped, projects need no re-encryption; other sessions are signed out.
  • Forgot your password? Ask the administrator (or send a request from the sign-in page) for a one-time password. After signing in with it, choose a new password and enter your recovery key to unlock your existing projects. Without the recovery key, existing projects cannot be decrypted by anyone.
  • Sign out removes your key and the local recovery copy from the browser. Delete account removes the account and all its projects.

My projects & autosave

File → My projects (Ctrl+O) lists every project stored for your account with its size and modification time. For each project you can Open, Rename, Copy (duplicate), ⤓ Download (encrypted projects download still encrypted) and Delete. The search box filters by name..

Saving

  • Autosave (on by default, see My account): a few seconds after each change the project is saved to the server. The status next to the project name shows “Saving…”, “Saved 14:02”, “Not on server” or an error.
  • Save (Ctrl+S) saves immediately; Save as copy creates a new project.
  • Conflicts: if the same project was changed in another tab or on another device, OpenPrism does not silently overwrite it. You choose to keep the server version, save yours as a copy, or overwrite.
  • A local copy is also kept in the browser for crash recovery (not for encrypted projects); it is removed when you sign out.

Storage quota & archiving

Each account has a storage quota — 256 MB by default (the administrator may set a different value) — and a maximum size per project (25 MB by default). The project browser shows how much you use.

From half of the quota (128 MB) OpenPrism asks you to offload older projects to your own computer:

  1. Open File → My projects.
  2. Click ⤓ to download a project (or open it and use File → Download encrypted project file to archive it with a password).
  3. Store the file safely (lab drive, institutional archive), then Delete the project from the server.

To work on an archived project again, use File → Open / upload project file: plain and encrypted .oprism files are both accepted (encrypted files ask for their password). The project opens for viewing and editing and — with autosave on — is stored on the server again.

When the quota is full, saving is refused with a message until space is freed; nothing already stored is lost.

End-to-end encryption

Every project saved on the server — contents and name — is encrypted in your browser with your personal data key (AES-256-GCM, fresh random IV per save). The server refuses unencrypted projects.

  • Your password is stretched with PBKDF2-SHA-256 (600 000 iterations, random salt per account) into 64 bytes: the first half is the key-encryption key (stays in the browser), the second half the authentication key (the server stores only an scrypt hash of it).
  • The random data key is created in your browser and stored on the server only wrapped by the key-encryption key and, separately, by your recovery key.
  • In the browser the unlocked key is a non-extractable WebCrypto key (usable but not readable by scripts), deleted at sign-out. The local crash-recovery copy is encrypted with it too.

Encrypted files

File → Download encrypted project file creates a portable file encrypted with a password of your choice (AES-256-GCM, PBKDF2 600k) for archiving or sharing. Opening it asks for its password and decrypts locally; downloading again lets you keep that password or choose another. Plain .oprism files can also be downloaded and uploaded.

Requirements and limits. Browsers allow this cryptography only over HTTPS (or localhost) — OpenPrism serves HTTPS by default. Encryption protects stored data; analyses send the analyzed table to the server for computation (in memory only).

Recovery key

When you create your account (or after a reset without your old key), OpenPrism shows a recovery key such as K7QM-2XRA-… (32 characters). It is a second key that unlocks your data key. Copy it, download it or print it, and keep it safe (password manager, locked drawer).

  • You need it only if you forget your password and the administrator resets it.
  • My account → Create new recovery key replaces it (the old one stops working).
  • Neither the server nor administrators have it. If both password and recovery key are lost, existing projects cannot be recovered; you continue with a new, empty key.

Administration console

Administration happens in a separate console on a different port (47219 by default) that answers only on the server computer itself: http://127.0.0.1:47219/. Requests from other computers — or with a foreign host name — are refused. Administrator accounts are separate from user accounts and cannot sign in to the user application.

First start

Until setup is complete the application shows “Server setup required” to everyone. On the server computer open the console: a wizard asks for the administrator name and password, whether users may register themselves, and default limits. On later starts the administrator already exists. Alternative: python run.py admin create <name>.

Users

  • Create user: enter the user ID and a one-time password (or generate one); the user chooses a personal password at first sign-in and their keys are created in their browser.
  • One-time password for forgotten passwords: sign-in works again; existing projects need the user’s recovery key.
  • Disable / Enable, Delete (account and all its projects); per-user storage, project size, RAM and CPU per analysis, analyses per minute.

Server settings

Allow or forbid self-registration; default limits; database backup (only hashes and ciphertext). Add/remove administrators, change your password, answer reset requests, and review the audit log. Administrators see user IDs, sizes and dates — never contents.

Production operation

  • Server: cheroot, a production multi-threaded HTTPS server (32 threads, OPENPRISM_THREADS); each calculation runs in a separate worker process with per-user memory/CPU limits.
  • Service: install deploy/openprism.service (systemd) so it starts at boot and restarts on failure; on Windows use NSSM or the Task Scheduler.
  • Logs: <data>/logs/openprism.log, rotated at 10 MB × 10. One line per request; bodies, query strings and cookies are never logged.
  • Backups: back up the data directory (openprism.db, tls/) or use Download database backup in the console.
  • Certificates: --cert/--key, or a reverse proxy (nginx, Caddy) plus --http.
  • Docker: docker compose up -d; create the administrator with docker exec -it openprism python run.py admin create admin (the console stays inside the container’s localhost).
  • Updates: stop the service, update code and dependencies, start again; data are kept.

Reporting your statistics

A reproducible methods section states:

  • What n is (animals, patients, independent experiments — not technical replicates) and the value of n for every group.
  • Which test was used, whether it was paired, one- or two-tailed, and the multiple-comparison method.
  • What error bars show (SD, SEM or CI).
  • Effect sizes with confidence intervals and exact P values, not only asterisks.
  • How outliers and missing values were handled, and any data transformation.
  • For curve fits: the equation, constraints, weighting, and whether replicates or means were fitted.
  • The software: “Statistical analyses were performed with OpenPrism 0.2 (SciPy, statsmodels).”

Example: “Data are mean ± SD of n = 8 mice per group. Groups were compared by ordinary one-way ANOVA followed by Dunnett’s multiple comparisons test against vehicle. Drug B increased the response by 12.3 units (95% CI 9.3 to 15.4; adjusted P < 0.0001).”

FAQ & troubleshooting

An analysis is greyed out.

It does not apply to this table type. For example, nonlinear regression needs an XY table and two-way ANOVA a grouped table. Create a table of the right type and paste the data.

“Analysis could not be completed”.

Read the message: typically not enough values, a non-numeric cell (shown in red), or a variable that must be 0/1. Fix the data — the analysis re-runs automatically.

My curve fit is “ambiguous” or the CI is huge.

The data do not define all parameters. Constrain a parameter, add data points spanning both plateaus, provide better initial values, or choose a simpler equation.

The fitted curve does not appear on the graph.

Open the graph and tick the analysis under Show analysis results on graph.

Significance brackets are missing.

Only significant comparisons are shown by default; tick Include non-significant. Brackets need a linked t test, ANOVA, Kruskal-Wallis or two-way ANOVA result.

The graph looks different after export.

Exports use the size set in Appearance. Set the final size before exporting so fonts keep their proportions.

“Cannot reach the OpenPrism server”.

The Python server must be running (python run.py). Your data stay in the browser (autosave) until it is back.

How do I cite OpenPrism?

Cite the software name, version and URL of the repository, and the underlying libraries (SciPy, statsmodels) where appropriate.

Scripting & API

The statistics engine is a normal Python package and can be used in scripts and notebooks:

from openprism.tables import make_table, parse_table
from openprism.stats import run

t = parse_table(make_table("demo", "column",
        [{"name": "Control", "reps": 1}, {"name": "Treated", "reps": 1}],
        [[1.2, 2.3], [1.5, 2.9], [1.1, 2.5]]))
result = run("ttest", t, {"welch": True})
for section in result["sections"]:
    print(section["title"], section["rows"])
